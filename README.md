# Harbor — Import Operations Dashboard

เว็บทดลองภาษาไทยสำหรับนำเข้า Excel กรองตาม Header ดู Dashboard และส่งออกรายงาน ทุกคนที่มีลิงก์ดู อัปโหลด และอัปเดตข้อมูลร่วมกันได้ ไม่มีล็อกอินหรือ PIN ตามขอบเขตรุ่นนี้ ไฟล์จริงของผู้ใช้ไม่อยู่ใน repository หรือชุดส่งมอบ

## เริ่มใช้งาน

ใช้ Python 3.12:

```bash
cd /path/to/Test-for-EDI-Developer
bash scripts/setup.sh
bash scripts/start.sh
```

แอปใช้พอร์ต 8000 ฐานข้อมูลเริ่มต้นอยู่ `data/dashboard.sqlite3` เปลี่ยนได้ด้วยตัวแปร `DATA_DIR` ข้อมูลอยู่ฝั่งเซิร์ฟเวอร์และคงอยู่หลังรีสตาร์ตเมื่อใช้ DATA_DIR เดิม ในคลาวด์นี้ใช้ checkout เดิม `/workspace/Test-for-EDI-Developer` ไม่ต้องสร้าง Git worktree

## ความสามารถ

- นำเข้า `.xlsx` ทุกชีตที่มี Header ตามต้นฉบับ ตรวจ Header และชนิดข้อมูล เก็บคอลัมน์เพิ่มเติม รวมถึง PO หากมี
- แสดงรายการใหม่ อัปเดต ซ้ำ และผิดรูปแบบก่อนบันทึก ต้องยืนยันอัปเดตและยืนยันข้ามแถวผิดรูปแบบ
- ตรวจซ้ำด้วย `Job I + Invoice No + CTNR NO.` ตัดช่องว่างเกินและเทียบแบบไม่แยกตัวพิมพ์ใหญ่/เล็ก มี unique key ในฐานข้อมูล
- ตรวจไฟล์เดิมและรายการเปลี่ยนแปลงด้วย SHA-256 เก็บประวัติก่อน/หลังแก้ไข และป้องกัน preview เก่าเขียนทับข้อมูลที่ผู้ใช้อื่นเพิ่งแก้
- Filter ตาม Header เลือกประเภทวันที่/ช่วงวันที่ ค้นหาเลขอ้างอิง กรอง Carrier/สถานะ ตารางแบ่งหน้าและเปิดรายละเอียดได้
- Dashboard จำนวนงาน/Invoice/ตู้ไม่ซ้ำ งานค้าง แนวโน้ม ATA สัดส่วนส่งตรงเวลา ตู้ตามสายเรือ และระยะเวลาของขั้นตอน
- Excel มีชีตข้อมูลและ `Job totals`, CSV รองรับภาษาไทย, PDF ใช้ Export → PDF แล้วเลือก Save as PDF ในเบราว์เซอร์ เป็นรายงานสรุป Dashboard พร้อมกราฟและตัวกรอง
- รีเฟรชข้อมูลร่วมกันทุก 30 วินาทีเมื่อหน้าต่างทำงานและไม่ได้เปิด dialog

## กติกาข้อมูล

1. Cartons/CBM เป็นยอดรวมต่อ Job นับครั้งเดียว ยอดของ Job เดียวกันต้องตรงกันทุกแถว หากแก้ยอดต้องนำเข้าครบทุกแถวของ Job นั้น
2. เมื่อกรองพบเพียงบางตู้ของ Job ยอด Cartons/CBM ยังเป็นยอดเต็มของ Job ที่พบ ไม่ใช่ยอดจัดสรรต่อตู้
3. CTNR NO. Count เก็บและแสดงเป็นจำนวนตู้จากไฟล์ ส่วน KPI ใช้หมายเลข CTNR NO. ไม่ซ้ำ เพื่อไม่รวมตู้ซ้ำในหลาย Invoice
4. แยกวันรับเอกสารครั้งแรกและวันรับเอกสารแก้ไขล่าสุด ถ้ามีวันเดียว ช่องแก้ไขล่าสุดว่าง ถ้ามีสองวันเท่ากันเก็บทั้งสองค่าตามต้นฉบับ
5. วันส่งจริงว่างถือว่ายังไม่ส่งมอบ ไม่ใช้ Status Declaration / รหัส 409
6. เกินกำหนด: ยังไม่ส่งมอบและ Delivery Plan ก่อนวันนี้ ตามเวลา Asia/Bangkok
7. ส่งช้า: วันที่ส่งจริงหลัง Delivery Plan เทียบระดับวัน อัตราตรงเวลาคิดจากรายการส่งแล้วที่มีแผนเท่านั้น
8. ระยะเวลาแต่ละขั้นตอนใช้วันเริ่มแรกถึงวันสิ้นสุดสุดท้ายของ Job ภายในข้อมูลที่กรอง ต้องมีข้อมูลครบทุกแถวในกลุ่ม ไม่รวมช่วงย้อนเวลา
9. เหตุผลแก้ไขเอกสารเป็นประวัติ ไม่ตัดสินว่าเป็นปัญหาที่ยังค้างอยู่
10. ถ้าคีย์ซ้ำแต่ข้อมูลต่างกันภายในไฟล์ ปฏิเสธไฟล์เพื่อให้ผู้ใช้แก้ไข ถ้าเหมือนกันข้ามรายการซ้ำ

## รูปแบบไฟล์

Header อยู่แถวแรก ตามชื่อใน `app/importer.py` ไม่ต้องเรียงตำแหน่งเดิม Status Declaration ไม่บังคับ วันที่รองรับ Excel date, YYYY-MM-DD, DD/MM/YYYY, FileNameDate แบบ YYYYMMDD และช่องรับเอกสาร YYYY-MM-DD HH:MM:SS YYYY-MM-DD HH:MM:SS

สูตร Excel ต้องวางเป็นค่าก่อนอัปโหลด ไฟล์ `.xls` ต้องบันทึกเป็น `.xlsx` ก่อน ข้อมูลจริงไม่รวมใน Git, archive, image หรือชุดทดสอบ

สร้างข้อมูลสมมติสำหรับทดลอง:

```bash
.venv/bin/python scripts/make_demo.py /tmp/harbor-demo.xlsx
```

## Deploy และลิงก์แชร์

ดู [DEPLOY.md](DEPLOY.md) และ `render.yaml` ซึ่งเตรียม Blueprint พร้อม Persistent Disk 1 GB ต้องมีบัญชี Render และแพ็กเกจที่รองรับ disk ตรวจสอบราคาปัจจุบันก่อนสร้างบริการ ยังไม่มีการ Deploy บน Render หรือ URL สาธารณะจากงานนี้

## ขอบเขตรุ่นทดลอง

- 10 MB / 10,000 แถวต่อไฟล์ และสะสมสูงสุด 100,000 รายการ เป็นขีดจำกัดป้องกันโหลดเกิน ไม่ใช่ผลรับรองความเร็วที่ขนาดนั้น
- FastAPI + SQLite WAL หนึ่ง instance/worker อ่านพร้อมกันได้ เขียนด้วย transaction
- Import/Export ทำใน worker thread ตรวจไฟล์พร้อมกันได้สองงาน ยังไม่มีคิวงานถาวรแบบ distributed
- มีการทดสอบผู้อ่านพร้อมกัน 30 รายในสภาพแวดล้อมพัฒนา ไม่ใช่ load test ระยะยาวบน Render
- ไม่มีบัญชีผู้ใช้ ประวัติระบุไฟล์ ค่าก่อน/หลัง และเวลา ไม่ระบุตัวบุคคล ผู้ถือ URL เข้าถึงข้อมูลและแก้ผ่านการนำเข้าได้
- หากขยายเป็นหลักล้านแถว: ใช้ PostgreSQL, object storage, durable job queue สำหรับ Import/Export และตารางสรุปกราฟ แล้วทดสอบโหลดใหม่

## ทดสอบและสำรองข้อมูล

```bash
.venv/bin/python -m unittest discover -s tests -v
DATA_DIR=/var/data python scripts/backup.py
```

ชุดทดสอบใช้ข้อมูลสมมติและฐานข้อมูลชั่วคราว ไม่แตะฐานข้อมูลจริง ตัวสำรองใช้ SQLite backup API ที่รวมข้อมูลใน WAL ด้วย ควรเก็บสำรองแยกจาก disk ของแอป หากกู้คืนให้หยุดบริการก่อนแทนฐานข้อมูลและตรวจสอบก่อนเริ่มใหม่

ทดสอบเบราว์เซอร์เพิ่มเติม (ต้องติดตั้ง Chromium):

```bash
.venv/bin/python -m pip install -r requirements-browser.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python tests/browser_smoke.py
```

หากมี Chromium ของระบบอยู่แล้ว ตั้ง `CHROMIUM_PATH=/usr/bin/chromium` แทนการดาวน์โหลด browser ตัวทดสอบจะเริ่มเซิร์ฟเวอร์และฐานข้อมูลชั่วคราวเอง ตรวจ Import/Export, การใช้ข้อมูลร่วมกัน, mobile/tablet/desktop และการเก็บข้อมูลหลัง restart ผลลัพธ์ภาพและ PDF อยู่ `test-results/` และไม่รวมใน Git
